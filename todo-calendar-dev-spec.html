需求整理

产品目标是把传统 TODO List 和时间表结合起来：用户先在右侧创建可拆分的任务，再通过拖拽把任务或任务块安排到左侧的周视图或月视图中。页面需要兼顾效率和审美，核心体验应接近“轻量项目计划工具”，而不是普通列表应用。

主布局左侧时间安排区占 70%，右侧任务栏占 30%。
任务能力支持预计时间、自定义拆分块数和每块时间。
排期视图左侧提供周安排与月安排两种模式。
拖拽排期任务栏任务可拖到周时间格或月日历日期中。
重要高亮任务或日期可标记极重要，并在列表、周视图、月视图中突出显示。
计时能力支持目标倒计时、专注计时器和固定时长倒计时器。
完成归档当天任务在右侧体现；完成后变绿，未星标的次日自动隐藏。

必须包含的功能

  • 添加任务：任务名称、预计总时间、备注、优先级可作为首版字段。
  • 拆分任务：用户可自定义拆分块数，也可手动调整每块时间。
  • 右侧任务栏：展示未安排、部分安排、已安排任务，宽度固定约 30%。
  • 周安排：顶部显示周一到周日，并包含日期；左侧显示一天内时段。
  • 月安排：以月历形式展示日期，每天展示已安排任务摘要。
  • 视图跳转：点击月历中的某一天，直接切换到该日期所在周的周安排。
  • 重要事项：任务和日期均可标记为极重要，视觉上高亮显示。
  • 计时功能：支持目标倒计时、正向计时器和固定时长倒计时器。
  • 完成与纪念：右侧当天任务可点击对勾完成，完成后变绿；任务可星标保留为当天纪念，未星标完成任务第二天不再显示。

首版建议边界

  • 先做本地数据持久化，不接后端账号系统。
  • 先支持桌面端和基础响应式，移动端可作为后续增强。
  • 先实现任务块级拖拽，不急于实现多人协作、提醒通知和复杂重复任务。
  • 月视图先承载日期级安排，精确起止时间由周视图完成。

技术栈

推荐使用 Vite + React + TypeScript 作为基础技术栈。Vite 适合快速开发和轻量构建，React 便于抽象复杂组件状态，TypeScript 能让任务拆分、排期实例和拖拽 payload 的数据结构更稳定。

领域推荐方案原因备选方案
构建工具Vite启动快、配置少、适合 React 单页应用。Next.js，若后续需要服务端渲染或账号体系再考虑。
UI 框架React + TypeScript日历、拖拽、任务拆分都依赖较复杂的状态建模，类型约束能减少歧义。Vue 也可行，但与 Vite + React 的需求假设不一致。
拖拽@dnd-kit/core现代、可访问性较好，适合自定义网格与任务块拖放。react-beautiful-dnd 不适合作为新项目首选。
日期处理date-fns函数式、体积小，适合周起始、月历网格、日期格式化。dayjs，API 更接近 Moment 风格。
状态管理Zustand比 Redux 更轻，适合任务、排期、当前视图等客户端状态。React Context，首版简单时可用，但后续容易臃肿。
计时实现Date.now() + setInterval + Zustand目标倒计时按分钟刷新即可，正向计时器可按秒显示；不需要引入复杂计时库。若需要后台提醒或系统通知，再增加 Web Notifications 或 Service Worker。
样式方案Tailwind CSS 或 CSS Modules若追求精美 UI 和快速迭代，Tailwind 适合；若追求样式隔离，CSS Modules 更稳。Styled Components，运行时成本略高。
持久化localStorage 起步，后续迁移 IndexedDB首版数据量小，localStorage 足够；若支持历史、附件或大量任务，再切 IndexedDB。后端 API + 数据库，适合登录同步版本。
测试Vitest + Testing Library与 Vite 集成好，适合测试时间计算、任务拆分和组件交互。Playwright 用于后续端到端拖拽测试。

展示过滤规则

function shouldShowInDayView(task: Task, selectedDate: string, today: string): boolean {
  if (task.status !== 'done') return true;
  if (task.completedDate === selectedDate && task.isStarred) return true;
  if (task.completedDate === today && selectedDate === today) return true;
  return false;
}

该函数表达的是普通日视图和右侧任务栏的显示逻辑。未星标的已完成任务第二天不再显示，但数据仍保留；如果后续增加“历史统计”或“完成记录”页面，可以从完整数据中读取。

界面结构

应用主界面建议采用固定工作台结构：左侧是排期画布，右侧是任务侧栏。周视图和月视图共享同一套任务安排数据，只是展示粒度不同。

顶部工具栏

放置应用标题、周/月视图切换、今天按钮、上一周/下一周或上一月/下一月按钮。后续可加入搜索和全局设置。

左侧排期区

周视图以时间格为主，月视图以日期格为主。该区域承担 drop target，并负责展示已安排任务。

右侧任务栏

任务栏用于创建、拆分、筛选、拖拽和查看当天任务。当天已安排或日期级待定的任务都应在右侧体现，任务卡片提供对勾完成按钮和星标纪念按钮。

周视图与月视图

周安排

顶部列头固定为周一到周日，并显示具体日期，例如“周一 8/3”。左侧时间轴建议以 30 分钟为最小粒度，视觉上可按 1 小时分隔增强可读性。

  • 拖入任务块时，根据 drop 位置推算日期与开始时间。
  • 任务块高度按时长映射，例如 30 分钟对应一个基础格高度。
  • 同一时间段冲突时，可先阻止放置并提示，后续再支持并排展示。

月安排

月视图是日历网格，每一天展示当天已安排任务的摘要。用户将任务拖入某一天时，可先创建“日期级安排”，若需要精确时间，再点击当天进入周视图细调。

  • 每个日期格显示最多 3 条任务，超出时显示“+N”。
  • 点击日期切换到该日期所在周，并高亮目标日期。
  • 月视图拖入任务默认进入待定时间段，例如当天的“未定时段”。

核心交互

拖拽需要围绕“任务块”而不是整条任务设计。一个任务可以被拆成多个块，每个块有自己的时长和安排状态；这样才能满足“时间也对应分割，可由用户自定义”的要求。

交互场景触发方式系统行为需要验证的规则
创建任务用户在右侧表单输入任务信息生成任务和默认任务块，可默认按总时长生成一个块任务名非空；预计时间大于 0；时间单位统一为分钟
拆分任务用户选择拆分块数或手动添加块生成多个 TaskBlock，每块有独立时长所有块时长之和不应超过任务预计总时长，除非用户确认调整总时长
拖到周视图任务块拖入具体日期与时间格创建精确起止时间的 ScheduleEntry目标时间段不能越界；冲突策略需明确
拖到月视图任务块拖入某个日期格创建日期级安排，时间可标记为未定月视图不能丢失任务块时长；日期必须有效
点击月历日期用户点击某一天切换到该日期所在周，并滚动或高亮到对应日期列周起始固定为周一；跨月日期也应正确跳转
移除安排用户将已排期任务拖回任务栏或点击删除删除 ScheduleEntry，任务块恢复为未安排不能删除任务本体，除非用户明确选择删除任务
标记极重要用户在任务详情或日期设置中打开重要标记任务卡、周视图任务块、月历日期格显示高亮样式任务级高亮和日期级高亮需要同时支持；日期级高亮不应自动改变所有任务优先级
启动计时用户从任务卡、已安排任务块或计时面板启动创建运行中的计时器实例，并在页面显著位置展示当前计时同一时间建议只允许一个运行中计时器，避免多个任务同时计时造成理解混乱
完成任务用户点击任务卡上的对勾按钮任务或任务块切换为完成态，卡片变绿，并记录完成日期完成动作不等于删除；是否次日继续显示取决于星标状态
星标纪念用户点击任务卡上的星标按钮任务在完成后仍保留在对应日期，并显示星标星标只影响历史展示和纪念保留，不应自动改变任务完成状态

每日任务与完成

右侧任务栏不仅展示待安排任务，也要体现当前选中日期的任务。用户在周视图、月视图或右侧任务栏中安排到某一天的任务，都应进入该日的右侧任务列表，方便用户在当天集中查看、完成和星标。

当天任务栏

当用户选中某一天，右侧任务栏优先展示该日任务，包括精确安排到某个时段的任务和月视图拖入日期但尚未定时的任务。任务卡片需要显示任务名、时间信息、拆分块状态、完成按钮和星标按钮。

  • 未完成任务保持普通卡片样式，可以继续拖拽调整时间。
  • 完成任务点击对勾后变为绿色，表示当天已经做完。
  • 完成后的任务可以继续点击星标，作为那一天的纪念保留。

次日显示规则

已完成但未星标的任务在第二天自动从右侧任务栏和普通日视图中隐藏，避免历史任务干扰当天计划。已完成且星标的任务会一直保留在对应日期，并在月历日期格、周视图任务块和右侧任务栏中显示星标。

  • 隐藏不等于删除，历史数据仍保存在本地，可用于后续统计。
  • 星标任务只固定在完成当天，不应复制到之后的日期。
  • 如果用户取消星标，且该任务已完成并不是今天的任务，则它应从普通视图中隐藏。

高亮与计时

新增功能分为两组：极重要高亮用于提高任务或日期的视觉优先级，计时能力用于帮助用户感知距离目标的剩余时间或记录当前专注时长。它们不改变任务拆分和排期的基础逻辑，但会影响任务卡片、周视图、月视图和顶部工具栏的展示。

极重要高亮

用户可以把某个任务标记为极重要，也可以把某一天标记为极重要。任务级高亮跟随任务在右侧任务栏、周视图任务块和月视图日期摘要中出现；日期级高亮作用于日历日期格和周视图对应日期列。

  • 任务级字段建议为 importance: 'normal' | 'important' | 'critical'。
  • 日期级高亮建议单独建模，不要把它混入任务优先级，避免语义冲突。
  • 极重要样式建议使用暖色边框、浅红背景、轻微发光阴影，并保留文字可读性。

目标倒计时

目标倒计时用于显示当前时间距离任务目标时间或重要日期的剩余时间。它可以绑定任务的 targetAt，也可以绑定日期高亮的 targetAt。

功能用途展示位置关键规则

正向计时器记录当前任务已经投入的时间顶部浮层、任务卡、任务详情从 00:00 开始累加；支持暂停、继续、结束并写入实际用时
固定时长倒计时器用于专注工作或短时冲刺计时面板、任务详情、迷你悬浮条用户设置时长后递减；结束时给出明显视觉提示

倒计时格式规则

function formatTargetCountdown(diffMinutes: number): string {
  if (diffMinutes <= 0) return '已到期';

  const days = Math.floor(diffMinutes / 1440);
  const hours = Math.floor((diffMinutes % 1440) / 60);
  const minutes = diffMinutes % 60;

  if (days >= 3) return `${days} 天`;
  if (days >= 1) return `${days} 天 ${hours} 小时`;
  return `${hours} 小时 ${minutes} 分钟`;
}

该格式函数应放在 shared/utils/time.ts 中，并由任务卡、月历日期格和顶部计时展示复用。倒计时建议每分钟刷新一次，不需要每秒刷新，以减少无意义渲染。

数据模型

数据模型建议拆成任务本体、任务块和排期记录三层。任务本体描述“要做什么”，任务块描述“这件事如何切分”，排期记录描述“某个任务块被安排到哪里”。

TypeScript 类型草案

type TaskStatus = 'todo' | 'partial' | 'scheduled' | 'done';
type BlockStatus = 'unscheduled' | 'scheduled' | 'done';
type ScheduleViewSource = 'week' | 'month';
type Importance = 'normal' | 'important' | 'critical';
type TimerMode = 'stopwatch' | 'countdown';
type TimerStatus = 'idle' | 'running' | 'paused' | 'finished';

interface Task {
  id: string;
  title: string;
  notes?: string;
  estimatedMinutes: number;
  priority?: 'low' | 'medium' | 'high';
  importance: Importance;
  targetAt?: string;  // ISO datetime，用于任务目标倒计时
  isStarred: boolean; // 完成后是否作为当天纪念保留
  status: TaskStatus;
  completedAt?: string;
  completedDate?: string; // YYYY-MM-DD，用于判断历史日期展示
  createdAt: string;
  updatedAt: string;
}

interface TaskBlock {
  id: string;
  taskId: string;
  title?: string;
  durationMinutes: number;
  order: number;
  status: BlockStatus;
  isStarred: boolean;
  completedAt?: string;
  completedDate?: string; // YYYY-MM-DD，拆分块级完成时记录
}

interface ScheduleEntry {
  id: string;
  taskId: string;
  blockId: string;
  date: string;       // YYYY-MM-DD
  startTime?: string; // HH:mm，月视图日期级安排可为空
  endTime?: string;   // HH:mm，月视图日期级安排可为空
  viewSource: ScheduleViewSource;
}

interface ImportantDay {
  id: string;
  date: string;       // YYYY-MM-DD
  title?: string;
  importance: Importance;
  targetAt?: string;  // ISO datetime，用于日期目标倒计时
}

interface TimerSession {
  id: string;
  mode: TimerMode;
  taskId?: string;
  blockId?: string;
  status: TimerStatus;
  startedAt?: string;
  pausedAt?: string;
  finishedAt?: string;
  durationMinutes?: number; // 倒计时模式必填
  elapsedSeconds: number;   // 正向计时与暂停恢复都依赖该字段
}

组件职责

  • TaskSidebar 管理任务列表、创建入口和筛选。
  • TaskCompletionButton 负责对勾完成动作，写入完成时间并触发绿色完成态。
  • TaskStarButton 负责星标纪念动作，决定完成任务是否在历史日期继续显示。
  • TaskSplitEditor 处理拆分块数、每块时长和总时长校验。
  • WeekView 渲染周一到周日与时间轴，并提供精确 drop target。
  • MonthView 渲染月历和日期级 drop target。
  • ScheduleBoard 控制周/月视图切换和日期导航。
  • CountdownBadge 负责目标倒计时文案，不直接关心任务来源。
  • TimerPanel 负责正向计时和固定时长倒计时的启动、暂停、继续、结束。

状态职责

  • tasks 保存任务本体。
  • taskBlocks 保存拆分后的任务块。
  • scheduleEntries 保存任务块的安排位置。
  • completedAt、completedDate 和 isStarred 用于完成态展示、星标纪念和次日隐藏。
  • importantDays 保存日期级极重要标记和目标时间。
  • timerSessions 保存计时器历史，activeTimerId 指向当前运行实例。
  • ui 保存当前视图、当前周、当前月、选中日期和弹窗状态。

视觉与体验方向

这个应用的差异点不只是功能，而是“更方便且精美”。视觉上建议使用柔和背景、玻璃拟态卡片、轻量阴影和高对比任务色块，让排期结果一眼可读。

柔和渐变背景 半透明任务卡片 拖拽时高亮可放置区域 任务块按时长映射高度 月历任务摘要最多三行 冲突放置即时提示 当前日期和目标日期明显高亮 极重要事项使用暖色强调 倒计时徽标保持短文案 计时器运行时显示迷你悬浮条 完成任务绿色显示 星标纪念任务显示星形标识
建议先设计 7 个关键状态：空状态、任务正在拖拽、已有多项任务排期、极重要事项高亮、计时器运行中、完成绿色态、星标纪念态。只要这些状态精致，整体产品质感就会明显提升。

待确认问题

以下问题会影响后续实现复杂度，建议在开始编码前确认。若不确认，也可以按本文建议的首版边界推进。

时间粒度

周视图最小时间格建议为 30 分钟。如果需要 15 分钟粒度，拖拽定位会更细，但界面密度也会更高。

冲突策略

首版建议禁止同一时间段重叠。后续可支持并排展示、自动顺延或冲突提醒。

月视图精度

月视图拖入任务后，是直接分配默认时间段，还是只分配日期待定，需要根据产品体验选择。

未完成任务跨天

已完成未星标任务第二天隐藏规则已经明确；未完成任务第二天是继续显示为逾期，还是回到待安排区，需要后续确认。

倒计时绑定对象

目标倒计时可以绑定任务，也可以绑定日期。首版建议两者都支持，但在界面上明确来源，避免用户分不清是任务截止还是日期事件。

计时器并发

首版建议同一时间只允许一个运行中计时器。若允许多个计时器并发，需要额外设计全局管理面板和冲突提示。

数据同步

首版建议本地持久化。若需要多设备同步，则需要增加登录、后端 API 和数据库设计。
